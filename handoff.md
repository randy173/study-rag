# study-rag Handoff & Architecture Guide

## What We're Building
A robust, decoupled full-stack RAG (Retrieval-Augmented Generation) study assistant that ingests textbook PDFs, stores them as vector embeddings in ChromaDB, and serves conversational question-answering with verified source citations via a Flask REST API and modern React frontend.

## Architecture & Dataflow

```
[Offline Ingestion Pipeline: ingest.py]
Textbook PDF(s) in data/ 
  → PyMuPDF block extraction (sort=True, headers/footers stripped)
  → Adaptive Tolerance Chunker (Target ~800 chars, ±150 window, sentence snapped)
  → Deterministic MD5 ID generation (source + page + text)
  → Zero-cost ONNX Embeddings (all-MiniLM-L6-v2) or OpenAI
  → Persist in ChromaDB (chroma_db/)

[Backend API: server.py (Flask @ Port 5000)]
POST /api/chat { message, history, top_k, temperature }
  → Multi-Query Optimizer (Typo correction, ordinal translation, sub-queries)
  → ChromaDB top-k deduplicated similarity search
  → Strict Contextual Question Answering (LCEL create_stuff_documents_chain)
  → Returns { answer, citations: [{source, page, text}], search_queries, latency_ms }

[Frontend UI: frontend/ (React + Vite @ Port 3000)]
React SPA (Vanilla CSS design system, Google Fonts Outfit & Inter)
  → Real-time chat feed with auto-scroll and markdown rendering
  → Collapsible citation drawers with exact page badges
  → Dynamic query breakdown chips
  → Live vector database status card & tuning sliders (k, temperature)
```

## Stack
| Component | Tool / Model | Rationale |
|---|---|---|
| PDF Parsing | PyMuPDF (`pymupdf`) | Fast, block-aware reading order (`sort=True`) for multi-column textbooks |
| Chunking | Adaptive Tolerance Chunker | Soft boundary window [650–950], sentence-snapped overlap, zero orphan fragments |
| Embeddings | Local ONNX `all-MiniLM-L6-v2` | 100% Free, runs offline locally with zero API keys or rate limits |
| Vector DB | ChromaDB (local persistence) | Cosine distance, local disk persistence in `chroma_db/`, idempotent MD5 upserts |
| Backend API | Flask + Flask-CORS | Lightweight, high-performance REST API with JSON endpoints |
| LLM | Groq (`openai/gpt-oss-120b` via `GROQ_KEY`) | Blazing fast inference, free tier, excellent reasoning |
| Frontend | React + Vite (Vanilla CSS) | Modern glassmorphism UI, responsive sidebar, verified citation drawers |

## Setup & Quickstart

### 1. Configure OpenAI API Key
Edit `.env` and paste your key:
```env
OPENAI_API_KEY=sk-proj-...
```

### 2. Install Dependencies
```powershell
py -m pip install -r requirements.txt
```

### 3. Run Ingestion
Make sure your textbook PDF is inside `data/`, then run:
```powershell
py ingest.py --reset
```
*Note: Using `--reset` wipes any old fragmented collections and cleanly indexes using adaptive tolerance chunking. Subsequent runs without `--reset` are idempotent.*

### 4. Launch the Study App
```powershell
py -m streamlit run app.py
```

## Key Architectural Decisions & Safeguards
1. **Separation of Concerns:** Ingestion and querying are completely decoupled so Streamlit reruns never re-read PDFs or re-embed chunks.
2. **Textbook Multi-Column Preservation:** `page.get_text("blocks", sort=True)` avoids interleaving text across columns.
3. **Idempotency & Cost Control:** Chunk IDs are MD5 hashes of `source + page + text`. Duplicate runs do not create duplicate embeddings or bill OpenAI.
4. **Follow-up Handling:** `create_history_aware_retriever` condenses pronoun-laden follow-ups (e.g., *"Can you give an example of that?"*) into complete standalone queries before querying ChromaDB.
5. **Hallucination Prevention:** The system prompt instructs the LLM to reply *"This topic is not covered in your textbook."* if the retrieved context does not answer the question.
